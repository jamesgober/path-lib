# v1.1.0 - Private directories

`path-lib` 1.1 added directories that are private to the current user on every operating system. It is an additive release: everything in 1.0 behaves exactly as before.

## What `path-lib` Is

Application and OS directory resolution for Linux, macOS, and Windows. `App` resolves the data, config, cache, logs, state, runtime, temp, and documents directories of one application for the current user, the whole machine, or one chosen folder. Sub-paths built on those directories are validated before they exist, and the filesystem operations refuse to overwrite, follow links, or delete critical paths. Zero runtime dependencies.

```toml
[dependencies]
path-lib = "1.1"
```

## New in 1.1.0

**`App::ensure_private(kind)`** and **`App::create_private(kind, sub)`** create directories that other users cannot read, for logs, audit records, crash reports, keys, and anything else that must stay with the account that runs the program.

```rust
use path_lib::{App, Kind};

let app = App::global("hivedb")?;
let logs = app.ensure_private(Kind::Logs)?;     // owner-only, even in global scope
let keys = app.create_private(Kind::Data, "keys")?;
# Ok::<(), path_lib::Error>(())
```

- **Unix:** mode `0700` (subject to the process umask), also for `Scope::Global`, where `ensure` uses `0755`.
- **Windows:** before 1.1 a new directory inherited its parent's access control list, which under `%ProgramData%` or a portable root can let other users read it. A private directory is now created with a protected list: full control for the current user, `SYSTEM`, and `Administrators`, nothing for anyone else, and no inheritance from the parent. Files and directories created inside inherit the same list. The list is part of the `CreateDirectoryW` call, so the directory is never open, even for a moment.
- Missing parents are created the same way. A directory that already exists is left as it is, and a symbolic link where the directory should be is refused.

`ensure` and `create` are unchanged, so nothing that worked with 1.0 changes behaviour.

The Windows access control list is set through a small hand-written binding (`OpenProcessToken`, `GetTokenInformation`, `ConvertSidToStringSidW`, `ConvertStringSecurityDescriptorToSecurityDescriptorW`, `CreateDirectoryW`); the crate still has no dependencies. Tests read the list back from the system and check that it is protected and names only those three accounts.
